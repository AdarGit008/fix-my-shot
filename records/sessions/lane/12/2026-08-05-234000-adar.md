**Ranking model** (`scoring/leverage.ts`, sport-agnostic; the app injects the
evaluation closure and the sport plugin injects display decor): each candidate
fix (violated + measured + deducting tier — style flags are legitimate
variation, unmeasured principles must never become advice) ranks by
`atStake + slope`:
- `atStake` — the points the principle currently holds down, now a first-class
  `PrincipleResult` field computed where the violation depth is known (stone
  ceiling loss / guideline deduction). This term is load-bearing: binary
  proxies have NO local slope (a presence flips, it doesn't lean), and pure-FD
  ranking would bury exactly the faults the library injects.
- `slope` — the ADR's finite-difference sensitivity proper: central difference
  of that stake per ±1-step perturbation of each editable parameter (the
  ADR-0009 subset: 21 hinges ±1.5°, ball position ±2 cm), one-sided at
  feasibility edges, max over parameters.

**Stability gate** (ADR-0008's load-bearing clause; SPEC acceptance #5): the
whole ranking is recomputed under K=3 seeded (mulberry32, fixed seed),
gate-validated micro-jitter contexts; a fix whose rank position ranges wider
than ONE across contexts is suppressed (rank-jumpers teach noise; adjacent
swaps are tolerated), and survivors order by median leverage across contexts.
Held by test: for every faulted library pose, a near-identical pose (±0.35°
hinge jitter, clamped + gate-valid) returns the SAME top fix.

**Feasibility model** (documented in `apps/web/src/report/index.ts`): stability
contexts are poses in their own right → full three-check gate; FD probes live
in the ε-neighbourhood of a valid context → phase-envelope clamp + root-height
re-grounding (the generator's ~1 mm floor penetration target, so leg
perturbations don't float/spear the floor and poison contact/balance readings),
with the full authority check elided for the interactive budget — a probe is
measured, never committed or shown. Measured cost: **p50 12.7 ms** for a full
report with 3 fixes (≈200 probe evaluations), 1.0 ms for a clean pose — 8×
inside the SPEC §11.7 ≤ 100 ms budget.

**Clusters + cues** (`basketball/src/cues.ts`): every scored principle carries
one of the four BEEF-style clusters (base / eyes / elbow-alignment /
follow-through) and an external-focus cue speaking at the target/ball/arc/floor
(ADR-0005, acceptance #6). The discipline is enforced by test: an unsanctioned
cue may name NO anatomy (word-boundary blacklist); exactly 4 rows use the
ADR-0009 escape hatch and record their sanctioned internal wording
(stance-width, foot-stagger, ball-on-finger-pads, hand-behind-under — body
geometry with no honest external referent).

**Report schema**: `packages/core/schema/report.schema.json` (draft-07 subset)
— grade ∈ [0,100], phase, per-principle results (tier/criterion/measured/
satisfied/deduction/atStake), ranked fixes (cluster enum + cue + leverage ≥ 0,
`additionalProperties: false` everywhere — raw per-parameter numbers cannot
ride along). Validated in-test against every report the library produces, with
a hand-rolled ~80-line checker (no new dependency).

**Verified end-to-end** across the library: every faulted pose returns a
non-empty ranked list of real violations (style-only faults correctly return
flags and NO fixes); a broken written-in-stone ALWAYS tops the list; reports
are deterministic, fixes included.
